# 易经入门学习网站 PRD

版本：1.0｜日期：2026年10月22日｜状态：需求基线，待云端实施

为大众初学者制作一个以读懂《周易》原典为目标的学习网站。第一版交付8节入门短课、64卦基础资料、16道理解练习和本机学习进度，采用清雅新中式设计，先提供有访问控制的私有预览。

当前阶段只完成PRD。切换云端环境并确定GitHub仓库后，再启动goal执行开发、校验和交付。

# 产品目标与边界

目标用户是对《易经》感兴趣、尚不能独立识读卦象和卦爻辞的大众初学者。核心问题是术语多、原文难懂、缺乏学习顺序；网站需要让用户知道从哪里开始，并能带着方法回到原文。

首轮学习的成功标准是：用户可以识别阴阳爻和上下卦，分清卦辞与爻辞，按正确顺序定位六爻，借助导读阅读一个未学过的卦。首版不承诺让用户掌握全部易学流派。

**用户已确认：** 系统入门、面向大众、8节课与64卦的完整入门站、读懂原典为主、本机保存进度、清雅新中式、先私有预览。

**实施默认：** 暂用站名“易学”；界面和本站讲解使用简体中文；原典保留所选来源字形并提供必要释词；每课约8至12分钟；全站课程可自由访问。

首版不包含起卦与占筮工具、AI解卦或聊天、注册登录、跨设备同步、社区、付费、内容管理后台、全套历代注疏和整部《易传》译注。网站内的账号系统不属于首版；私有预览由托管平台控制访问。

# 学习流程与页面

主要流程：进入首页 → 开始或继续课程 → 阅读图文讲解 → 完成两题并看解析 → 标记本课完成 → 进入下一课。阅读中可跳转相关卦的资料页，再返回课程。

| 页面 | 必须提供的内容与操作 |
| --- | --- |
| 首页 | 一句话说明学习目标；“开始学习”或“继续学习”主入口；8课学习路线；已完成课数；64卦入口。 |
| 入门课程列表 | 8课编号、标题、学习目标、预计时长和完成状态；允许跳读，无强制解锁。 |
| 课程详情 | 本课目标、分节讲解、至少一个对应图解或原文例子、两题练习、答案解析、上下一课和相关卦链接。 |
| 六十四卦索引 | 按通行卦序展示64卦；卡片显示卦名、序号、卦象和上下卦；支持卦名及序号搜索、上下卦筛选、清空条件和无结果状态。 |
| 卦详情 | 卦名与读音、卦序、卦图、上下卦、原创导读、卦辞、六条爻辞、必要释词和来源；返回索引、上一卦、下一卦。 |
| 学习记录 | 已完成课数、各课状态、最近学习的课程入口；说明记录保存在当前浏览器；提供需二次确认的重置操作。 |
| 关于与内容来源 | 说明原典与原创讲解的区别、版本来源和使用说明；说明进度保存范围。 |

搜索匹配简繁卦名别名及1至64的阿拉伯数字；去除首尾空格。搜索与上下卦筛选同时生效，默认按卦序升序。首版不增加全文语义搜索。

# 八节入门课大纲

| 课次 | 主题 | 学习结果 | 图解或练习重点 |
| --- | --- | --- | --- |
| 01 | 从哪里开始读《易经》 | 认识本网站的学习范围，区分经文、传文和本站导读。 | 拆解一张卦的资料页；识别文字类型。 |
| 02 | 阴爻与阳爻 | 识别两种基本爻画，理解“爻”和“卦”的区别。 | 实线与断线图解；识别爻画。 |
| 03 | 认识八卦 | 看懂三爻结构，认识八卦名称及常见取象。 | 八卦对照图；根据结构辨认，不要求先背全表。 |
| 04 | 从八卦到六十四卦 | 看懂上卦、下卦和六爻结构。 | 上下卦分区高亮；识别组合。 |
| 05 | 卦辞与爻辞怎么读 | 分清整卦文字和具体一爻的文字。 | 原文分层标注；判断句子所属层次。 |
| 06 | 爻位与爻题 | 能从下往上定位初、二、三、四、五、上，并读懂九、六爻题。 | 点击卦图某一爻显示对应爻题；位置匹配。 |
| 07 | 乾坤阅读示范 | 把卦图、卦辞、爻辞和导读联系起来。 | 乾坤对照；单列用九、用六，避免误作第七爻。 |
| 08 | 独立读一卦 | 按“看结构—读卦辞—定位爻辞—回看导读”的步骤阅读。 | 用屯、蒙做综合练习，提供回看前置课程的入口。 |

每课固定采用“目标—讲解—图文例子—两道理解题—解析—下一步”的结构。术语首次出现时就地解释；手机端不得依赖鼠标悬浮才能读取解释。图解服务于结构识读，不加入与教学无关的复杂动画。

每题为单选题，至少有一个可理解的干扰项，提交后明确显示选择结果、正确答案、解释和对应知识点。解释性或有流派分歧的观点不设计成唯一正确的客观题。

# 六十四卦内容标准

每卦必须包含：唯一卦序、简繁卦名与读音、六爻阴阳结构、上下卦、完整卦辞、六条带爻题的爻辞、150至250字左右的原创入门导读、影响理解的关键词解释、具体来源链接及版本记录。不以几句通用励志话代替每卦导读；首版不要求逐句白话翻译全部爻辞。

六爻数据统一按从下到上的顺序存储。卦图视觉上方为上爻，下方为初爻；文字列表按初爻至上爻阅读。上下卦分区、卦名与图形必须来自同一份结构化数据。

乾卦的用九与坤卦的用六以独立附加文本展示，不计入六爻数量。来源中的《彖》《象》《文言》等内容不能混入卦辞或爻辞；课程需要引用时，单独标明篇名。这个区分可直接在[乾卦原文页](https://zh.wikisource.org/wiki/周易/乾)和[坤卦原文页](https://zh.wikisource.org/wiki/周易/坤)核验。

首版采用[维基文库《周易》各卦页](https://zh.wikisource.org/wiki/周易)作为数字文本底稿，导入时逐页记录固定版本链接和取得日期，形成可复核的文本快照。网站运行时读取随代码部署的内容，不依赖第三方网页实时抓取。来源页的概述和历史作者归属不能未经核查直接作为课程事实。

保留来源字形；对异体字、通假字和影响阅读的字词作注释。标点整理或正文校订需留下记录，不能为追求简体化而静默改写原典。本站白话导读与教学案例原创，明确标注为辅助理解的解释；现代译注、编辑说明及其他附加材料的授权与署名要求单独核对。

# 练习和学习记录

1. 进入课程后记录最近学习的课程。首版恢复到课程入口，不要求精确恢复滚动位置。
2. 两题均提交后显示解析，并启用“完成本课”按钮；用户点击后计入完成进度。答错不阻止完成，可重新作答。
3. 已完成课程可以重读、重做，完成数量不会重复累加；不设置排行榜或通过分数门槛。
4. 浏览器本地保存完成课程、最近课程和最近一次已提交答案；刷新或关闭页面后仍可恢复。
5. 首页的新用户入口指向第一课；有最近课程时显示“继续学习”；全部完成后显示复习入口。
6. 存储被禁用或写入失败时，阅读和练习仍能使用，清楚提示当前无法保存。数据损坏时忽略无效记录并给出提示，不导致页面白屏。
7. 重置记录需用户确认；换设备、换浏览器或清理浏览器数据后不会自动恢复。首版不上传学习记录，不引入第三方行为追踪。

# 视觉与交互要求

整体采用米白背景、墨色正文、少量朱红强调与细线分隔。中文标题可采用宋体风格，正文优先清晰易读。视觉气质安静、现代，避免大面积装饰压缩阅读空间。

桌面阅读区限制行宽，课程目录作为辅助导航；手机端改为单列，主要操作容易触达。正文基础字号不小于16px，行高约1.8；重要触控目标至少44px。当前页面、选中答案、错误提示和焦点状态均需可辨认。

卦象使用SVG或CSS绘制，保证阴阳爻、上下卦和选中爻在不同尺寸下清楚可见，同时提供文字说明。关键操作支持键盘；信息不能只靠颜色表达。遵循减少动态效果的系统设置，不使用自动播放音效、闪烁或强制长动画。

# 工程要求与接口

若目标GitHub仓库已有技术栈和工程规范，优先沿用。若为空仓库，默认采用无后端的静态HTML、CSS与JavaScript ES Modules，实现独立内容数据、页面组件和本地进度存储；这符合首版规模，也便于私有托管。

课程和卦数据与界面代码分离，使用稳定标识关联。最小数据模型包含课程、题目、卦、来源记录和本地学习状态；保存格式带版本号，后续更新内容时保留已有完成状态，不因排序变化错配课程。

首版不增加服务端API或数据库。内部模块边界为内容读取、检索筛选、答题反馈和进度读写。页面采用可复制的hash路由，覆盖首页、课程列表、课程详情、卦索引、卦详情、学习记录和来源页；刷新深链接正常，未知路径显示可返回首页的提示。

提供本地启动说明、内容更新说明、可重复执行的内容校验和测试命令。网络请求不参与核心阅读与答题流程；不把凭据写入源码、PRD或提交历史。
